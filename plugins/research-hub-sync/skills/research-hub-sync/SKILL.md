# Research_Hub 3-Party Sync Skill

This skill standardizes state synchronization between **local coding agents** (Antigravity, Codex CLI/Desktop) and **cloud reasoning workspaces** (ChatGPT, Gemini Web + Google Drive `Research_Hub`) using three fixed per-project artifacts:
- **`01_Logbook` (Google Doc)**: Append-only reverse-chronological ledger of verified experimental results, exact denominators, and root-caused failures.
- **`02_Studio` (Google Doc)**: Crisp top Focus Board (`vYYYYMMDD-N`) holding the active problem, approved plan, acceptance criteria, and next handoff.
- **`03_CodeSnapshot.md` (`< 500 KB` Markdown)**: Single-file tree + core source + AST fallback summary generated by `scripts/pack_codesnapshot.py` for zero-RAG-fragmentation cloud architecture reviews.

---

## 1. Resolving Project Document IDs

Always look up the bound IDs in the active workspace's `AGENTS.md` (`## Research_Hub 固定文档绑定`) or your central `REGISTRY.md` (see `examples/REGISTRY.example.md` in this plugin):

| Project Key | Local Workspace | Drive Folder ID | `01_Logbook` Doc ID | `02_Studio` Doc ID |
| :--- | :--- | :--- | :--- | :--- |
| `ProjectAlpha` | `E:\Project\ProjectAlpha` | `<DRIVE_FOLDER_ID>` | `<LOGBOOK_DOC_ID>` | `<STUDIO_DOC_ID>` |
| `BioLM` | `E:\Project\BioLM` | `<DRIVE_FOLDER_ID>` | `<LOGBOOK_DOC_ID>` | `<STUDIO_DOC_ID>` |

> Never create duplicate `Logbook` or `Studio` documents when fixed IDs are already bound in `AGENTS.md` or `REGISTRY.md`.

## 2. Standard Operations by Surface

### A. In Antigravity (`gdocs` & `gdrive` CLI plugins)
Ensure `$HOME\.gemini\antigravity\bin` is on `PATH` and **stage temporary sync markdown on a non-system data drive (e.g. `<workspace>/_tmp/doc_sync`, NEVER on `C:` when `local-storage-rules` is enabled)**:

```powershell
$env:PATH = "$HOME\.gemini\antigravity\bin;" + $env:PATH

# 1. Read Studio or Logbook before starting ("继续当前方案")
gdocs readonly read <STUDIO_DOC_ID>

# 2. Pull -> Edit -> Sync back cleanly (preserving formatting & tables)
New-Item -ItemType Directory -Force -Path "<WORKSPACE>\_tmp\doc_sync" | Out-Null
gdocs readonly pull <DOC_ID> "<WORKSPACE>\_tmp\doc_sync\working.md"
# ... edit working.md ...
gdocs mutate sync <DOC_ID> "<WORKSPACE>\_tmp\doc_sync\working.md" --prefer-local

# 3. Refresh & upload <500KB CodeSnapshot
python "$HOME\.gemini\config\plugins\research-hub-sync\scripts\pack_codesnapshot.py" `
  --project <ProjectKey> --root "<WORKSPACE>" --out "<WORKSPACE>\_tmp\<ProjectKey>_03_CodeSnapshot.md" --upload --folder-id <DRIVE_FOLDER_ID>
```

### B. In Codex Desktop / CLI
- Use the connected Google Drive / Google Docs connector directly on the fixed `<DOC_ID>` from `AGENTS.md` or `REGISTRY.md`.
- Generate local `03_CodeSnapshot.md` via `scripts/pack_codesnapshot.py` using `--config projects.json` or `--root <WORKSPACE>`.

## 3. Document Entry Schemas

### `01_Logbook` Reverse-Chronological Entry Template
Insert directly below `## 二、 实验与核验记录（按日期倒序，最新在最上）` (and update the top summary table if valid baselines changed):

```markdown
### [YYYY-MM-DD | <Run-ID_or_Topic> | <Antigravity / Codex>]
- **动作与配置**：简述改动、脚本/配置版本、本地或计算集群输出路径。
- **样本量与评测口径**：明确分母（如 `10,000` episodes / `n = 16,098`）、数据划分与异常回退规则。
- **关键结果 / 失败留档**：核心指标数值，或失败现象与根因定位。
- **结论状态**：`[有效]` / `[失败留档]` / `[取代旧记录 <Old-Run-ID>]`
```

### `02_Studio` Top Focus Board Fields
Keep the 5-row table at the top of `02_Studio` concise:
1. **看板版本号与更新时间**：`vYYYYMMDD-N · YYYY-MM-DD` (always increment `N` on edit!)
2. **当前待解问题**
3. **已选定方案（Current Plan）**
4. **验收条件**
5. **下一棒交接（Next Action）**
